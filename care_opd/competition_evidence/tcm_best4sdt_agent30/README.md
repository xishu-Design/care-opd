# TCM-BEST4SDT 最终留出30例四系统专家盲审

本目录用于生成一项可冻结、可盲审、可审计的中医开放式病例比较实验。正式实验采用
`local_product`：它通过神农三言医生端的真实产品路由调用
CARE-OPD 后训练模型，并启用 Graphiti、Mem0、SQL 对话上下文和冻结完整
`backend/app/content/data` 的本地结构化检索。LightRAG 不是该主轨的必需组件。

实验比较四个系统：

1. 神农三言完整项目（上述 `local_product` 产品配置）；
2. HuatuoGPT-3-8B 本地医疗模型基线；
3. GLM-4-9B-0414 本地中文模型基线；
4. InternLM3-8B-Instruct 本地中文模型基线。

三个对照接收与神农三言相同的病例和作答要求，但它们是冻结公开权重模型，并非复制
神农三言角色路由、知识检索、记忆与安全编排的同构 Agent。因此本实验回答的是
“完整项目端到端回答能否获得更高专家偏好”，不能将差异单独归因于 CARE-OPD，
也不代表临床疗效。

## 正式运行边界

- `local_product`：30题专家盲审的正式主轨。推理时使用本包冻结的完整 QZBC 内容数据，
  在隔离数据库中完成结构化检索；同时保留真实角色路由、CARE-OPD、Graphiti、Mem0
  和 SQL 对话上下文。该配置不访问互联网，也不依赖耗时的 LightRAG 全量建库。
  QA 扩展索引仅在已有且通过审计时启用；缺失时明确关闭，不影响医生轨的结构化知识检索。
- `live_product` LightRAG 增强轨不属于本次正式盲审，也不是前置条件；如以后补跑，
  必须另立协议、运行根和报告，不能与本次结果混合。

`local_product` 不是锁定 Evidence Packet 的简化接口。病例仍只通过正式 `message`
字段进入医生端，系统在推理时自行检索和编排；冻结内容库不含这30题的参考答案，且在
任何模型生成前执行重叠审计。

## 任务冻结

- 上游：TCM-BEST4SDT Figshare v8，DOI `10.6084/m9.figshare.30615956.v8`；
- 组件：`TCM_SDT.json`，300例，CC BY 4.0；
- 文件 SHA-256：
  `d94711ac60db83e3a33c2c46b1d6efbf072565a22e8fd464f5f61b444860de59`；
- 最终留出样本：seed=`20260827-final-holdout`。先排除开发轮30例的病例 ID 及其规范化
  疾病诊断哈希，再在剩余病例的每个规范化疾病标签内按 SHA-256 取一例，按独立
  SHA-256 排名取30个不同疾病标签，最后独立打散题序；新旧两批在病例 ID 和诊断哈希
  上均不重叠；
- 选题、任务顺序和本地文本重叠审计均在四系统生成前冻结，
  `performance_based_selection=false`；
- 模型任务仅含病例 `instruction`。上游参考答案与疾病标签不进入任务文件、API 请求
  或专家盲码映射，四个生成系统也没有文件工具；
- 正式服务器增量包只携带该30题无答案任务、冻结选择清单与重叠审计；完整300例源文件
  和独立参考答案文件均不入包。运行时先核验三份冻结产物的预注册 SHA-256，再确认任务
  中不存在答案、诊断标签或金标准字段，因而推理进程不需要也不会打开参考答案；
- 冻结 QZBC 产品代码/内容快照可能含与本轮 TCM-BEST4SDT 无关的公开数据资源；这些资源
  不进入本轮活跃检索源集合，也不能作为病例答案使用。实际启用源集合另行冻结哈希并在
  推理前逐例执行重叠审计；
- 30例病例只通过 QZBC 正常 `message` 字段输入，单条消息不超过2000字符；
- 正式推理前，将30个冻结病例与本次实际启用的结构化知识源逐一执行规范化精确/近重复
  审计，并记录源文件与审计产物的 SHA-256。任一病例命中预注册阈值，整次运行在生成前
  终止。该审计不能证明基础模型预训练语料从未包含相似病例。

## 统一推理协议

四个系统收到完全相同的病例与六段式医生任务：病例要点、辨病辨证、病因病机证据链、
治则治法、方药思路与加减原则、鉴别/复核信息。方药只要求思路，不要求固定剂量，避免
把缺少可核验来源时的安全降级误测为专业能力不足。

生成参数冻结为 temperature=0、top_p=1、seed=42、最大输出1200 tokens。四个系统在
同一物理 GPU 上依次加载，避免并发资源差异。神农三言走隔离的 QZBC 医生端真实路由；
三个基线走本地 OpenAI-compatible 端点。四个系统均在新留出任务上从头运行，不复用
开发轮任何回答。

为使“记忆与对话连续性已启用”成为可检验事实，每道病例为神农三言分配独立账号，并
先通过正式产品接口写入同一条、不含病例事实的回答格式偏好。随后使用该账号提交病例。
不同病例的账号、SQL 历史、Mem0 namespace 和 Graphiti group 完全隔离。

神农三言每次调用必须同时留下机器审计：

- 本地结构化知识检索工具真实执行，且后端身份为 `local_knowledge`；有命中时必须
  返回可追溯 Evidence Packet，无匹配时必须显式记录为 `degraded`，不得伪造命中；
- Graphiti 路径非空，Mem0 命中该账号的角色记忆；
- ConversationContext 实际注入既往轮次；
- CARE-OPD 模型身份与冻结生成参数匹配；
- LLM、知识、图与记忆适配器均未回退；
- Evidence Packet、trace 与角色可见性满足医生端合同；
- 六节结构、病例来源引用、候选具体性、事实—判断链、条件化治法与方药方向、复核对象、
  整体降级、固定剂量、临床终局性、字符数和分句数均作为内容或安全审计维度保存；
- 上述维度不得用于拒收、重采样、删题或决定哪一次回答进入盲审。项目臂将其保存为辅助
  机器审计；四个系统均由专家按同一表格评价，并据此解释系统为何胜出或失分。

本实验采用选择中立合同：**每个系统每题只允许一份进入盲审的冻结输出；重试仅修复生成前
基础设施故障，一旦产生本题首个用户可见答案即固定该答案。** 无论答案是否缺节、过短、
拒答、推理不足或含安全风险，均不得以内容为由重新生成。执行身份、题目与哈希绑定、未访问
参考答案、产品栈实际参与、响应归属与持久化完整性仍是硬性资格条件。`degraded` 与 `fallback`
分开记录，安全降级可以保留，但不得把其他后端回退包装成完整系统结果。

## 专家盲审

每位专家、每道病例使用独立 A/B/C/D 映射；映射在系统×题目层近似平衡，专家之间也不
共享固定字母含义。专家对每题选择：

- A/B/C/D：唯一最佳；
- TIE：2至4份并列最佳；
- NONE：四份均不可接受；
- SKIP：无法评价并填写原因。

每道非 SKIP 题还必须标出不安全候选或填写 `NONE`。被标记为不安全的候选不能同时获得
最佳票。主指标为安全合格专家首选份额；并列按1/k分票，NONE保留在分母且四系统均得0，
SKIP排除。统计包含病例级10,000次 bootstrap 95%区间、神农三言对每个基线的配对差、
专家分层和专家一致性。若某系统三次生成前技术调用均未产生用户可见输出，整轮保持为
未完成并保留失败记录；修复基础设施后必须从全新运行根按同一冻结协议重跑，不能删除该题
或只汇报其余病例。
