# 证据布局适配开发对照 V1

本包只回答一个问题：冻结的视觉观察换成较熟悉的证据布局后，四个文本后端是否更好地使用已有信息？这不是完整原生医疗合同，不证明视觉训练、局部 Protect 或临床效果，也不自动解决期刊 scope。

## 固定的干预

| 项目 | 处理 |
| --- | --- |
| 系统提示、问题、requested_records、record_context | 与原版完全相同 |
| 证据 | `evidence.a/b.observation` 移至 `evidence_packet.retrieved_evidence[].summary` |
| source_id、record_id、origin | 原值保留 |
| 观察正文 | 原始字符串逐字保留，不剥围栏、不补 JSON、不替换 UNKNOWN |
| 输出格式、短答案要求、弃答规则 | 原版不变，不加新 output_schema 或重试策略 |
| 推理与评分代码 | 复用与源配置哈希一致的旧代码 |
| 模型、tokenizer、chat template、生成预算 | 必须与原缓存绑定一致 |

没有添加 `verified`、`approved` 或基于标签推导的可用性标记；没有把通用图表题伪装成 `student_analysis`。输入转换白名单不读取 condition、标签或模型旧答案。可逆转换检查确认没有丢失观察或来源。

## 默认预算和选择

- 默认卡 1，顺序加载 Clean-SFT、GKD、TROPD、CARE，始终只加载一个文本模型。
- 固定盐 20260918 + block_id 的 SHA256 排序选前三个完整块，每块保留全部六种条件。
- 18 个请求 × 4 个模型 = 72 次新文本生成；旧布局复用对应旧缓存，不做新视觉推理。
- 全部原数据已经被检查过，因此所有结果都是事后开发诊断。3 个独立块不能支撑稳定收益或显著性主张。
- 不按 CARE 的错误或前端是否正确选择样本，不自动扩大样本、改提示或按分数选择新旧输出。
- `BLOCKS` 只允许在首次准备时设定；本轮建议保持默认 3，之后改变数量必须使用新目录并披露。

## 隔离和锁定

原 source 目录只读。新 work 必须与其独立；不复制图像和权重，只封存所选任务、观察和旧响应。`prepare/check/preflight/run` 都不打开 gold 文件，只有所有模型完成后的 `score` 才核验并读取原 gold。

每个旧观察/响应有行封印、模型指纹、旧输入哈希核验；每个新响应保存输入哈希和旧响应的配对哈希。恢复只跳过已完成首输出，空输出、格式错误、length 都作为已完成保存，不因答错而重试。基础设施错误另外记录。源码、输入或软件栈漂移会中止，不能通过改 manifest 绕过。

原生责任区训练完全不变，所以本轮不能视为修复了 A/B 子字段的 Protect 粒度。旧/新生成发生在不同批次，虽然锁定软件、模型和贪心生成配置，仍应披露缓存对照的执行时间差。

## 运行和结果

完整命令见 `SERVER_COMMANDS.md`。需现有可用的 GPU Python 环境、四个原文本 checkpoint 和完成的 boundary 缓存。不需网络、VLM 权重、RAG、数据库或训练。

- `prepare`：CPU 源缓存审计、固定抽样、构建新提示。
- `check`：CPU 复核源/新缓存和提示，不读取标签。
- `preflight`：检查原 GPU 软件栈、四个 checkpoint 和 tokenizer 预算；不生成答案。
- `run` / `resume`：只补未完成的新文本输出，结束后自动评分。
- `status`：计数；正在写入时可能遇到未结束行，稍后重查，不修改文件。
- `score`：全部完成才允许汇总，旧结果不覆盖。

输出位于新 work 的 `summary/<指纹>/`。旧评分器的 strict 与 semantic 分开保留，空分母为 null。关注正常准确率、覆盖率、已回答准确率和有用且边界正确的联合端点；不以弃答率或单一保护率宣布成功。查看四个模型的适配前后变化，而非只看 CARE。

若卡住/退出，先查日志和 `infrastructure_errors.jsonl`。不要盲目删除锁、删坏行或改变冻结配置；磁盘部分写入需要保留现场后诊断。`resume` 不会终止其他 GPU 进程，也不绕过 CUDA/OOM 错误。
